1. CURRENT UI ARCHITECTURE
-------------------------------------------------------------------------------
- Shell: misuc::ui::MainWindow (already a QMainWindow) builds, in order:
  * menu bar (File/Edit/Help) via buildMenus()
  * a top TransportBar (custom-painted buttons, QWidget)
  * a left nav rail (navLogo QLabel + checkable QPushButtons) driving a
    QStackedWidget (pages_) of 5 real pages
  * a bottom StatusPanel
  * a 33 ms poll timer driving transport/service-state refresh
- Pages (all engine-backed, all WORKING):
  ProjectPage (name/tempo), EditorPage (+1320-line PianoRoll), MixerPage
  (real engine mixer + meters), AudioSettingsPage (device/tone/groove/monitor/
  gains/meters), ThemePage (presets/custom accent/glass).
- Theming: theme::k* inline tokens (Theme.h) + ThemeEngine::Palette (11 base
  colors, 8 presets, custom accent, glass material, QSS stylesheet, .misuctheme
  file + QSettings persistence, themeChanged signal). buildStyleSheet() has
  hard-coded hover/pressed colors and no QDock/QTab/ToolBar/StatusBar rules.
- Audio engine + Session schema: MUST NOT change semantics. Engine untouched.

-------------------------------------------------------------------------------
2. PROPOSED ARCHITECTURE  (Phase 1 target)
-------------------------------------------------------------------------------
A modular, dock-based DAW shell with a persistent global header and a
cross-app hint system. Structural, not a recolor:

  [ Global Header (QToolBar, spans full width) ]
    left   : navLogo + "MISUC" wordmark + project name
    center : compact TransportBar + metronome/count-in/loop + tempo spin
    right  : app CPU% / RSS / sample rate / buffer+latency / xruns /
             audio state / master mini meters (L/R + clip)
  [ Central workspace = QTabWidget with real tabs ]
    Project | Editor (Piano Roll) | Audio | Appearance
  [ Dockable panels ]
    Mixer dock (QDockWidget, bottom area, closable/floatable/movable/tabbable)
  [ QStatusBar ]
    left: HintBar (persistent contextual hints)   right: StatusPanel
  [ Menu bar ]
    File / Edit / Workspace / Help
    Workspace = layout presets (Default, Mixing, Piano Roll, Recording) +
                "Panels > Mixer" toggle; layout persisted via QSettings.

Everything a user can see is either a real control wired to the engine/session,
or intentionally absent (no fake Browser/Channel Rack/Playlist/plugins — those
are later phases and MUST NOT exist as mockups per §62).

5. MIGRATION STRATEGY
-------------------------------------------------------------------------------
- Stepwise, compile-clean at each step; shell swap happens LAST in the PR.
- Keep the exact public API the harness pins:
    MainWindow::{session(), sessionEdited(), setExportPathOverride(),
                 writeProject(), openProject(), menuBar()}
    EditorPage(Add/Remove/mute/track list/piano child), MixerPage strips,
    Fader::setValueDb/valueDb, ChannelStrip setters, ThemeEngine surface,
    AboutDialog fields, the "navLogo" QLabel objectName,
    and the default-theme pixel colors PianoRoll asserts (playhead/loop/clip).
- The nav rail is REMOVED from the visual, but navLogo QLabel survives inside
  the header (same objectName) so branding checks pass.
- QStackedWidget → QTabWidget for the central workspace; page order preserved
  so the first QListWidget child is still the editor track list.
- Mixer moves from page to QDockWidget; QDockWidget state is the unit of
  layout persistence (restoreState/saveState).
- Metronome/count-in become REAL (engine_.setMetronome) — currently the count-
  in button is cosmetic (an existing functional gap §31 fixed here).

6. THEME ARCHITECTURE  (Phase 1)
-------------------------------------------------------------------------------
- Keep ThemeEngine + 8 presets + custom accent + glass + .misuctheme.
- Add semantic tokens: backgroundSecondary, surface, surfaceElevated,
  surfaceGlass(Strong), borderSubtle, textSecondary, textMuted, textDisabled,
  accentHover, accentPressed(exists), selection, grid, playhead, loopregion,
  notebody, clipbody, clipwave, noteSelected, meterNormal/Hot/Clip,
  panelHeader, toolbar, button/Hover/Pressed, tooltipBg, hintBar, transport,
  gridRow, marquee.
- Theme-driven ones pushed from Palette on every apply (whole app re-colors);
  editor-neutral editor/playhead/clip tokens keep fixed stock values so
  composition readability is constant and the harness pixel checks stay green
  (documented as a later-phase item to make them accent-following).
- Default preset = premium charcoal glass: near-black workspace, layered
  charcoal surfaces, restrained coral accent, subtle translucent borders.
  No RGB/gaming styling (§55).

7. WORKSPACE ARCHITECTURE  (Phase 1)
-------------------------------------------------------------------------------
- Central QTabWidget: Project | Editor | Audio | Appearance (all real pages).
- Mixer QDockWidget (bottom); closable/floatable/movable; QSettings persists
